# Seeded course-content audit

The seed catalog is built in `src/main/java/com/studyspace/server/Bootstrap.java`. Chapters are linked by `course_id`, lessons by `chapter_id`, and quiz items by `chapter_id`; the seed identifies rows by parent ID plus title/prompt instead of relying on row position. `SeedContentAuditIntegrationTest` verifies those relationships, lesson coverage, difficulty levels, explanations, and rerun idempotency.

The audit found three LIFO/binary-search duplicates and two Kotlin/Compose duplicates copied into the wrong chapters. The repair script disables only those wrong-chapter copies; the correctly assigned questions stay active, and historical attempt snapshots stay unchanged. The source account had no enrollments or attempts in these two affected courses, so no learner history was impacted.

The course `mạng máy tính` owned by the demo instructor had a mixed database/network description, placeholder chapter/lesson, and generic questions. It had two classes, one learner, one completed lesson, and four attempts. The targeted repair corrected the description, chapter, lesson, and two question prompts/options/explanations while preserving IDs, class membership, learner progress, and quiz snapshots. API content and relationship counts were checked after repair. Both SQL repairs are safe to re-run: the network repair matches only the known malformed state and the duplicate repair only deactivates wrong-chapter copies.

The local portal catalog is not the same thing as the deterministic Bootstrap seed. It also includes user-authored data that existed before this audit. Both groups were checked separately; repairs are narrow and do not rename/delete unrelated teacher content.

Run the focused audit with `gradlew.bat test --tests '*SeedContentAuditIntegrationTest'`. Runtime counts may include instructor-created content; the audit test checks relationships and seeded minimum coverage rather than assuming IDs or hard-coded database row counts.
